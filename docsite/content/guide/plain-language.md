A host that lets someone ask in plain language puts a model in front of jaala: the model writes a program from the question, jaala checks it, and a program that doesn't check goes back to the model with its error. Package `nl` holds the parts of that every host would otherwise write alike ([#321](https://github.com/panyam/jaala/issues/321)). What the words mean, the model and the tool that serves it stay with the host. An engine-only host never imports `nl`.

Each front end is a Go module of its own, so what one depends on reaches only the hosts that import it: `go get github.com/panyam/jaala/frontends/nl` for this page, `frontends/nlmodels` for the local model clients below, and `frontends/mcp` and `frontends/cypher` for the [next]({{.Site.PathPrefix}}/guide/mcp-server/) [two]({{.Site.PathPrefix}}/guide/cypher/) pages. They're tagged with jaala, `frontends/nl/v0.1.N` beside `v0.1.N`. Up to v0.1.71 `nl` was a package inside jaala's own module, so a host moving past that tag requires the new module in its place.

The examples use the vocabulary from [Host options]({{.Site.PathPrefix}}/guide/host-options/): the `imports` and `pkg` relations, the standard predicates and the `deps` module.

## The card

`nl.Card` lists every relation and predicate a program can call, one line each: the signature, what a predicate needs bound before it runs, and the first line of the doc. A model reads it in place of the docs. The same vocabulary always gives the same text, so a host can keep it as a cached prompt prefix and pay for it once.

## The grammar

`nl.Grammar()` is the program syntax as a GBNF grammar, the form llama.cpp's `grammar` field takes ([#323](https://github.com/panyam/jaala/issues/323)). A model decoding under it can only write text that parses, so no retry is spent on a missing bracket or a misplaced `=>`. The fourth example above prints its first rules; the whole grammar is [`frontends/nl/testdata/program.gbnf`](https://github.com/panyam/jaala/blob/main/frontends/nl/testdata/program.gbnf).

It covers jaala's own spelling, the one these docs use: clauses separated by `; `, `not` for negation, the answer after ` => ` with `having`, `order by`, `after`, `limit` and `offset`. It leaves out the forms jaala reads only so people and agents can write other Datalogs (comments, a `.` ending, `?-`, `!atom`, see [Syntax]({{.Site.PathPrefix}}/guide/syntax/)), and a type that names another head variable (`?k`, `kind(?o)`), which only the parser can check. It allows one space or newline where the spelling has room for one, so a model can't spend tokens on blank space, and caps a name (a relation's segment, a variable, a unit) at 32 characters, so a model that wants to write prose can't run one name on until its token limit ([#340](https://github.com/panyam/jaala/issues/340)).

`nl.GrammarFor(v)` narrows it to a vocabulary ([#324](https://github.com/panyam/jaala/issues/324)). A call names one of `v`'s members at an arity it takes, and an argument whose type is a closed domain is a variable or one of the domain's values, so a model decoding under it can't write `edge(?a)`, a member that doesn't exist, or a misspelled kind. A program's own rules take names nothing at the root of `v` uses, so a call to any other name is a call to one of them, which the grammar can't check is defined. `nl.GrammarFor(v, nl.GoalOnly())` leaves rules out, so every call is a real member; that's the strictest form, for a small model asking one question. Both are built once per state of the vocabulary, as the card is.

Parsing, and with `GrammarFor` the names and counts, is all a grammar promises. Whether every variable is bound, and whether a rule a program calls exists, is still `Validate`'s, and its errors are the next section's.

## Errors a model can fix from

A program that can't run as written fails `Validate` and `Eval` with a `*datalog.CheckError`. Its message is the one the [error catalogue]({{.Site.PathPrefix}}/reference/errors/) lists, unchanged, and its fields say the same as data:

- `Kind` sorts it: `unknown`, `arity`, `unbound`, `type`, `stratify`, `definition`, `aggregate` or `answer`. A host counts failed programs by kind without matching on text.
- `Fix` says how to change the program, when the engine can tell: the vocabulary's suggestion for a name, or the program's own rule it likely means (`str.mine` for a rule `mine`, [#341](https://github.com/panyam/jaala/issues/341)), the signature for a call at the wrong arity, what to bind for an unbound variable. It's empty for a cycle through negation, where the fix depends on what the program meant.
- `Relation`, `Args`, `Var` and `Rule` say what the error is about.

A `Query` carries no positions: a host can build one in Go, and two parses of one text compare equal. So `datalog.Locate(text, err)` finds the place in the text instead, the call to `Relation` with `Args` arguments (in `Rule`'s clauses when it names one), else the first `?Var`. It returns a `ParseError`'s own position too, so one call places any error. `nl.Explain(text, err)` writes all of it the way a model reads it, the second example above: the message, the line with a caret under the place, and the fix.

## The loop

The translator puts the card and the errors together ([#325](https://github.com/panyam/jaala/issues/325)). `translator.New(v, pack, cfg)`, in the `frontends/nlmodels` module, takes the vocabulary, a pack and the models to ask, and `Ask(ctx, question)` asks the model for a program. It parses and checks the draft, and when it doesn't check, sends it back with `Explain`'s text and asks again, up to `Options.MaxTries` times (3 by default). The third example above is a scripted model, chakra's `StubProvider`, getting a name wrong once: the second request carries the first draft and its error, and the second draft checks. A reply wrapped in a Markdown code fence is read from inside the fence.

Each answer is held to `GrammarFor(v)`, or the host's own with `Options.Grammar` (none with `Options.NoGrammar`), when the model's provider takes a grammar. A provider that can't send one gets none. Every draft is checked anyway, so the grammar only saves tries.

The models are the host's: each `translator.Role` names a chakra `Provider` ([local models](#local-models)). The card and a few lines of instructions go as the system prompt. They're the same for every question over one vocabulary, so a provider can cache them. A host that can find the names in a question, as Declaire's `name.find` turns a short name into ranked ids, implements `nl.Grounder` and passes it as `Config.Grounder` (or as the pack's `Grounder`). The candidates go after the question with their values quoted, so the model copies a value rather than spelling it.

`Config.Fallback` is a second model, usually a bigger one, asked once the first runs out of tries. It starts a fresh conversation with the question, since the first model's drafts would only cost it tokens. A model that sends back a draft it was already told is wrong has stopped reading the errors, so that try is refused unchecked and the question moves to the fallback, or fails when there is none ([#340](https://github.com/panyam/jaala/issues/340)). With `Options.Base`, a program that checks is run too (with `Options.Eval`'s options, such as a `Budget`): an error is fed back like a check error, and a program answering nothing goes straight to the fallback, told that one did, or back to the same model when no fallback is left. That model is told which literal matched nothing and what it was first called with (`Report.Empty`, see [Host options](../host-options/), [#343](https://github.com/panyam/jaala/issues/343)), so it can change that call rather than guess, and whether the call matches anything by itself ([#348](https://github.com/panyam/jaala/issues/348)), which tells a wrong value from a wrong join. A small model quite often sends that same draft straight back, so the first time it does, the repeat doesn't end its turn. It's told again what matched nothing, which call to change and the grounded values, and the repeat's `Try` is marked `Reasked`, so a host can count whether asking again helped. A second repeat ends the turn as before ([#483](https://github.com/panyam/jaala/issues/483)). Being told which call failed wasn't enough for a 14B model on Declaire's questions: x05's model learned its `str.prefix(?g, "github.com/panyam/goapplib/")` matched nothing, first on `"time.Now"`, and sent the same draft four more times. So the translator also runs the goal once more without that literal and shows up to five values that the rest gives the literal's variables, such as the real spelling of `?g`'s ids (`EmptyAnswer.Without`, `Prompts.Without`). When the engine folded an equality like `?l = "mit"` into the atom it names, the equality is what's left out. Nothing shows when the literal sits in a rule, shares no variable with the rest, or the program came from a front end. A model call that fails moves to the fallback as well.

`Ask` returns the accepted `nl.Program` (its text, `Query`, rows when it ran, and the model that wrote it) and an `nl.Trace` of every try, also when it fails: the model, the text, the error and its `Kind`, tokens in, out and cached, latency, and, for a draft run over `Options.Base`, the `datalog.Report` of that run. An empty answer's error is an `nl.EmptyAnswer`, whose `Why` is the run's `Report.Empty`. `Kind` is a `CheckError`'s kind, or `parse`, `eval`, `empty`, `repeat`, `answer` or `model`, so a host counts where its retries went without reading messages.

## Looking before answering

A model drafting blind guesses at what the data holds, and on Declaire's questions most of a local model's failures were guesses that answered nothing: an edge kind, an attribute's value, an id's spelling ([#393](https://github.com/panyam/jaala/issues/393)). `Options.Actions` lets it look first. The model is offered four tools, and each one's result comes back to it:

- `look` with a `name`: a relation's signature and whole doc, or a module's members. A model often sends a plain word, as in `look interface`, and expects a search. A name that matches nothing gets the card lines of up to 10 members whose name or first doc line holds the word, with name matches first. When nothing holds it, the answer is what `find` would give. Without a Grounder, the model is told what `look` takes ([#512](https://github.com/panyam/jaala/issues/512)).
- `values` with a `target`: up to `Actions.Sample` (10) of one argument's values, as `pkg.license` or `pkg.1`, run as `pkg(_, ?v) => ?v limit 10`.
- `try` with a `draft`: it runs with at most `Sample` rows, and sends back its rows, or why it answered none, as an empty answer is explained.
- `find` with a `name`: the values a name may stand for, from the `Grounder`. Grounding the question up front guesses which of its words are names, and this lets the model ask about the one it's stuck on. Without a Grounder it isn't offered.

A reply that calls no tool is the answer, judged as a draft always is. An action doesn't spend a try. `Actions.Steps` (6) caps them per model, and once they run out the tools are taken away and the next reply must be the answer. An answer given while tools are offered costs one more call on a server that takes a grammar: a grammar covers a whole reply, and tool calling has its own, so chakra asks once more for the answer under the grammar. Some models can't call tools. Qwen2.5-Coder behind `llama-server --jinja` writes a call as JSON in its text, the server finds no call in it, and the model never looks ([#509](https://github.com/panyam/jaala/issues/509)). A role marked `TextActions` takes its actions in its reply instead. It is offered no tools, the prompt lists the actions, and every reply is held to a grammar of an action or a draft, so it costs no extra call. Once its steps run out, its next call is held to the draft's grammar, with a `try` line allowed before the draft. That line is dropped before the draft is judged. A model whose history holds its own `try` replies writes one more, and under the draft's grammar alone the word ran into the first name, as in `tryagainlater()` ([#512](https://github.com/panyam/jaala/issues/512)).

An action the model took already isn't run again and takes no step ([#517](https://github.com/panyam/jaala/issues/517)). The model gets back what it answered the first time, with a line saying so. The Runner doesn't count the call either, since jaala answers a tool call with chakra's free result (`agent.FreeResult`, v0.3.2), which the model reads as the call's result, and a text reply with `TurnEndVerdict.Free`. On Declaire's x04 the model cycled through `try`, `look`, `try` and `find`, and its turn ended on the Runner's step cap with nothing new run. The third repeat (`nl.MaxRepeats`) ends the actions, and chakra's `MaxFreeRefusals` is set to the same number. A greedy model given the same input writes the same reply, so a model that repeats an action twice in a row, or takes turns between two actions twice, also gets a note naming what it repeated. Where the provider takes a temperature, that one call samples at the fallback's 0.7. If the model is still repeating at the next call, its actions end, and its next reply is the answer. chakra's stuck detector finds the pattern, and jaala's key reads the action from a tool call or from a text reply. Since v0.3.4's preset it also catches one action coming back three times within six steps, as x04's `try`, `look`, `try`, `find`, `try` did, and the note goes as the user's message. An answer breaks the pattern, since a repeated draft already ends the turn. A local model and a frontier fallback can differ here, since the setting belongs to the `Role`. A host's own loop over an `nl.Session` reads the same text actions through `Session.TextActions` and `nl.ReadAction`. `Trace.Steps` records each action with what went back and what it cost, and `Report` counts steps and their tokens beside the tries, so the first-try rate still counts answers.

The loop doesn't read the drafts' language: a `try` goes through the front end as an answer does, and a front end that implements `nl.Prober` answers `look` and `values` in its own terms. Cypher's does, so a model writing Cypher asks for the values of `Package.license` and the probe runs as `MATCH (n:Package) RETURN DISTINCT n.license LIMIT 10`.

A draft that guesses a value's spelling, `"mit"` where the data holds `"MIT"`, is repaired by the translator itself when the conversation has seen the right one. The values it has seen are those a `values`, `try` or `find` sent back, plus the closed `Domain` of an argument whose check refused the constant. When a draft answers nothing, or the check refuses one of its constants, each quoted value the data doesn't hold as written but holds in exactly one other spelling (case and punctuation apart, so `"Apache 2.0"` meets `"Apache-2.0"`) is rewritten. The new draft is then checked and run again. If it answers, it's accepted as a `Try` of its own after the model's, with `Try.Repair` saying what changed, and `Report.Repairs` counts them. If it doesn't, the model's own draft is what goes back. The harness never picks between two spellings.

`Actions.Compact` sends the model one turn in place of the conversation: the question, each action and refused answer as a fact (`- values pkg.license` and what came back), and the last refusal whole. A small model's drafts get worse as its context grows, and the facts are what it needs from the turns. A fallback starts afresh, as it does without `Compact`.

`Actions.Build` lets the model write its program a literal at a time ([#514](https://github.com/panyam/jaala/issues/514)). Imagine a model asked about consul-template that writes `loc.home(?t, "github.com/hashicorp/consul-template", ?uri)` as the third of four literals. Written whole, the program answers nothing, and the model learns that only after it has written all four. With `add LITERAL` it appends one literal to its body, and the result is the body's rows so far, or why there are none, as `try` reports. So the wrong repo shows 0 rows at the literal that wrote it. `drop` takes the last literal off, and an `add` whose body doesn't check is refused and leaves the body as it was. Once the body is right, the model answers with the goal's tail alone, `=> ?p`, and the conversation puts it after the body. The grammar takes either a whole program or that tail. Each `add` or `drop` is a step, so a host using `Build` may want more `Steps` than the default 6. It needs jaala's own language, so a front end turns it off.

`Actions.Ledger` shows the model a ledger after the conversation on every call ([#514](https://github.com/panyam/jaala/issues/514)). It lists what the `look`, `values` and `find` actions found, then each draft the model tried or answered with and what that did. A small model loses a fact like "no node has kind module" a few turns back, and it resends a draft it was told was wrong. The translator writes each list into a chakra slot (`agent.NewSlotsWith`), under `Prompts.LedgerHeader`, sent as the user's message for that call alone, so it never joins the history. With `Compact` the one turn keeps the question and the last refusal, and the ledger carries the rest. A host's own loop reads it from `Conversation.Ledger`, and `Prompts.LedgerFound` and `LedgerTried` head its two lists.

`Actions.DraftFirst` has the first model draft once without the actions, as it would one-shot, before its turn with them ([#521](https://github.com/panyam/jaala/issues/521)). On Qwen2.5-Coder 14B the actions' prompt made the first draft worse: x05's one-shot draft passed, and its first draft under the loop swapped caller and callee. A draft that passes is the answer. A refused one starts the turn, where the first message carries it and its refusal under `Prompts.DraftFirst`. The conversation holds it as refused, so the model sending it again is a repeat. The loop can then only add passes to one-shot's, at the cost of one more model call. A host's own loop does the same with `Conversation.From`.

## Voting, escalation and a budget

One answer from a small model is one guess. `Options.Vote` draws more once a model has answered (`Vote.Drafts`, 3 in all by default, at once with `Vote.Parallel` for a model safe to call concurrently), judges each as an answer, and keeps the one whose rows most of them answer, the first among equals ([#393](https://github.com/panyam/jaala/issues/393)). Drafts agree when their rows match by value as a multiset, whatever their variables are called, and without a `Base` when they compile to the same program. A refused draft agrees with nothing. The vote is chakra's `Consensus`, with the accepted answer counted as its first draw, and each further draw gets its own seed when the provider takes one. The drafts only differ when the model samples: at temperature 0 a vote agrees with itself every time.

`Program.Confidence` carries what the translator knows about an answer: how many drafts agreed out of how many, whether it ran and answered rows, whether the pack's `Check` passed it, and how many actions came first. `Options.Escalate` moves an answer whose drafts agree less than that share on to the fallback, recorded in `Trace.Escalations`, and when the fallback answers nothing better, the first such answer comes back rather than an error. A host whose fallback is a frontier model or agent pays for it only on the questions the small model was unsure of.

`Options.Budget` caps the tokens (prompt and reply, every call together) and the time the translator spends, across actions, tries and votes. Once the calls so far have reached it, nothing more is asked, and `Ask` fails with a `*nl.BudgetSpent`. A vote the budget leaves no room for draws fewer drafts.

`Options.Abstain` lets the translator say it isn't confident rather than hand back an answer its vote disputes or fail without saying why ([#482](https://github.com/panyam/jaala/issues/482)). It's off by default, and each ground is the host's to switch on. `MinAgreement` abstains on an answer whose drafts agree less than that share (after `Escalate`, so a kept answer counts too), `NoAnswer` when the tries ran out with no draft accepted, and `Budget` when the budget ran out. The error is an `*nl.Abstained` with the `Reason`, the closest `Draft` (a draft that ran and answered nothing ranks above one the pack's `Check` refused, which ranks above one that didn't check) and its `Diagnosis`, the text the model was told. A host can answer "not confident" and give the caller that draft to finish. A model that fails, a cancelled call and a `Grounder` error stay failures, so a host can still tell "broke" apart from "not sure".

`Try.Class` sorts a refused try by what went wrong. `grounding` is a draft that ran and answered nothing, and `construct` one that didn't parse, compile or check. `semantics` is one the pack's `Check` refused, and `budget` one an evaluation budget stopped. `abstained` is a case the translator abstained on, counted apart from the failures so a wrong answer and an honest "don't know" aren't scored the same. `Result.Class` does the same for a case `Eval` scored, with a case that answered the wrong rows as `semantics`. `Report.Failures` counts the failed cases by class, and the report's summary counts votes and escalations.

## Front ends

A model needn't write jaala's syntax. `Options.FrontEnd` names a language it writes instead ([#354](https://github.com/panyam/jaala/issues/354)), and Cypher's is `cypher.NewFrontEnd(graph, examples...)` ([asking in Cypher]({{.Site.PathPrefix}}/guide/cypher/#a-model-writing-cypher)). The prompt is then the front end's card, instructions and examples, followed by the pack's `About` and data `Card` but not its jaala examples. The grammar sent is the front end's. Each draft is compiled before it's checked and run, and every refusal goes back as the front end explains it, in the draft's language and at its place in the draft. Everything else is unchanged: repeats, empty answers, the fallback and the pack's `Check`. An empty answer goes back at the draft's place too: `cypher.Explain` puts the caret under the pattern that wrote the literal `Report.Empty` ends at ([#386](https://github.com/panyam/jaala/issues/386)).

Each `Try` and the accepted `Program` record the `Language`, and `Program.Compiled` holds the jaala program the draft became. A compile refusal is the kind `compile`, or the front end's own, such as Cypher's `gap` for a construct jaala can't express yet. `Report.String` names the language, so a host can run one set of questions through both languages on one model and compare the two reports: first-try passes, tries, tokens and what was refused.

A front end is an interface in `nl` (`nl.FrontEnd`) that the front end's own module implements, since `nl` imports no front end.

## Local models

jaala runs no model. `github.com/panyam/jaala/frontends/nlmodels`, a module of its own so no host takes on HTTP clients it doesn't use ([#330](https://github.com/panyam/jaala/issues/330)), asks any [chakra](https://github.com/panyam/chakra) `Provider` ([#487](https://github.com/panyam/jaala/issues/487)). The host builds the provider, or names it in chakra's connections config, and jaala sends each request through it:

- llama.cpp's `llama-server`, through `agent.NewLlamaCppProvider`, gets the prefix as the system message, the prompt's grammar as `grammar`, so the model can only write text that parses, and `cache_prompt`, so the card is processed once.
- Ollama, through `agent.NewOllamaProvider`, takes no GBNF grammar (only a JSON schema), so the model writes freely and costs more tries; a host wanting the grammar held runs the same weights under llama.cpp.
- A hosted model (Anthropic, OpenAI, vLLM) through chakra's own providers. Anthropic takes no temperature, so set `Temperature` to nil there.

The translator asks the provider what it can send (`agent.CapabilitiesOf`), and sends the grammar, a vote's seed and a temperature only to one that takes them. The tokens a try reports are the server's own counts, with llama.cpp's cached prompt tokens. Here a stand-in for `llama-server` answers one program and prints what it was sent:

The tuning that goes with a model comes with it ([#490](https://github.com/panyam/jaala/issues/490)). `translator.New(v, pack, cfg)` takes the vocabulary, the pack and a `Config` naming the providers:

```go
t, err := translator.New(v, pack, translator.Config{
	Model:    translator.Role{Provider: local},
	Fallback: translator.Role{Provider: frontier}, // sent no temperature: Anthropic's provider says it takes none
	Base:     base,
	Vote:     &nl.Vote{Drafts: 3},
})
p, tr, err := t.Ask(ctx, "which tests reach the billing package?")
```

jaala picks what each role is sent. The model gets temperature 0 and the fallback 0.7, since the fallback is only asked once the model has failed. Both reply in at most 512 tokens. A role marked `Thinking` is a reasoning model, so it gets 3072 tokens and no grammar, which would hold the reply to a program from its first token, plus a line asking it to think the question through and put the program in a fenced block. Only the last fenced block outside `<think>` counts as its draft. A `Role`'s `Penalties` turn on chakra's sampling penalties (repeat, frequency, presence and DRY) for a model that repeats itself until its token limit, as `find(interfaceinterfaceinterface(...` did ([#517](https://github.com/panyam/jaala/issues/517)). Each kind goes only to a provider whose `CapabilitiesOf` lists it, so llama.cpp gets all four, Ollama frequency and presence, and Anthropic none. A `Role` can replace any of these, its `ThinkPrompt` the think line (`translator.DefaultThinkPrompt`), `Config.Options` edits the `nl.Options` last for anything `Config` doesn't name, and the `Translator` itself is what [jaala's MCP server](#serving-agents) takes for its `ask` tool (`mcp.Options.Translator`).

`Ask` runs on chakra's agent `Runner` rather than a loop of jaala's own ([#496](https://github.com/panyam/jaala/issues/496)), and each turn's `RunnerConfig` comes from chakra's graph-query preset (`presets.GraphQuery`, [#528](https://github.com/panyam/jaala/issues/528)). jaala supplies its own prompt, grammar, tools, retriever, ledger and judging, and swaps in its own action budget. jaala's half of a question is an `nl.Session`: the prompt, the grammar, the actions, and how a reply is judged. Each model's turn is a Runner turn whose answers a `Session`'s `Conversation` judges as it ends, sending a refusal back as the user's next message or stopping the turn. `look`, `values`, `try` and `find` are offered as tools until the model has used `Actions.Steps` of them, which costs one more call per answer on llama.cpp, since a grammar can't share a call with tools. A vote is chakra's `Consensus`, with the accepted answer counted as its first draw. Until #496 the loop was jaala's own, `nl.Translate`. A differential test held the Runner to that loop's decisions, try for try and request for request, before it went, and its tests and the two eval goldens moved over unchanged.

## Domain packs

The card says what a program can call, but not what the data holds or what a question in this domain usually looks like. A host says that once, in an `nl.Pack` passed as `Options.Pack` ([#344](https://github.com/panyam/jaala/issues/344)), so Declaire's code graph and Agni's schematics are each a pack over the same translator:

- `About` says what the data is about, in the words its users use. It opens the pack's part of the prefix, and jaala's MCP server ([#347](https://github.com/panyam/jaala/issues/347)) writes its instructions from it.
- `Card` says what the data holds that the vocabulary can't, such as which kinds and values a question will name. `nl.DataCard(ctx, base)` writes the generic half: each relation with how many facts it holds and, per argument, its values with how many facts hold each, or how many there are and the commonest when there are more than twelve. It counts every relation whole, so a host computes it once per data version and adds what only it knows, such as how its ids are spelled.
- `Examples` are questions with the programs that answer them, one or two per construct. How to call one relation belongs in its doc instead.
- `Grounder` grounds the question when the translator's `Config` names none.
- `Shape` says how the data is laid out as a graph: the relation holding each node's kind, the edge relations, and the attributes whose values are node ids ([#514](https://github.com/panyam/jaala/issues/514)). With it, the model may ask `paths FROM => TO`, where each end is a kind followed by literals over `?x`, such as `paths func str.glob(?x, "github.com/a/*") => func str.glob(?x, "github.com/b/*")`. jaala finds the joins between the two kinds, runs each on a few rows, and sends back the ones that answered, shortest first, so the model picks a join rather than writing one. A join comes back with no `limit`, so a model answering with it gets every row, and only the rows shown are capped ([#530](https://github.com/panyam/jaala/issues/530)). An end whose literals never mention `?x` is refused, since nothing would tie them to its node. A pack words the three refusals itself with `Prompts.PathsUsage`, `PathsNoKind` and `PathsUnbound` ([#532](https://github.com/panyam/jaala/issues/532)), and `nl.ParseEnds` returns each as an `*nl.EndsError` naming which one it was. The vocabulary can't say which kinds an edge joins when a node's kind is data, so `nl.KindGraph` reads it from the data. It reads every edge relation whole, so a host computes it once per data version and passes it as `Links`, as it does `DataCard`.
- `Preview` names, for a question, what the model sees a few rows of before its first draft ([#514](https://github.com/panyam/jaala/issues/514)). A relation shows its first five rows under its arguments' names, and a values target such as `pkg.license` shows its first five values. A small model guessed ids, kinds and repo names from the card and wrote `str.prefix(?c, "internal/")` over ids that start with a module path. The rows show it how the data spells them. The translator reads them once per question (`Session.Preview`) and puts them before the question through chakra's retrieval stage, on every call of a turn and in a vote's history. A value the preview showed also repairs a draft's guessed spelling, as an action's does. Nothing is shown without a `Base`.
- `Check` judges an answer that checked and ran: an error refuses the draft as `answer` and goes back to the same model with its text, as a check error does. It's for what makes an answer suspect in the domain, such as every value absent, or a hundred rows for a question asking for one.
- `Callables` lists relations that answer a question on their own once their arguments are filled, which the translator asks the model to pick from before it drafts ([below](#answering-with-one-call)).
- `Hint` says what your data holds where an empty answer matched nothing. It gets `Report.Empty`, with the culprit's `Relation` and `Args`, and returns text such as `no node kind "entity"; the kinds are package, func, type`. The translator adds it to the empty draft's feedback after jaala's own explanation, and the MCP server to an empty answer of `query`, `cypher` and `explain` ([#430](https://github.com/panyam/jaala/issues/430)). It runs once per empty answer, so keep it to a few lookups.

The pack's part goes after the card and the instructions, `About` and the examples as comments, so the prefix is still the same for every question and stays cached. The translator checks every example against the vocabulary before asking a model, and fails naming the first that doesn't check, so a pack can't teach a model a relation the vocabulary lacks. A host's test can call `Pack.Validate` and `Pack.Prefix` itself. Here `DataCard` writes the guide's data, and a pack whose `Check` expects one package refuses a first draft answering three:

### The words around the pack's

Everything jaala writes into a prompt around the pack's own text is the pack's to replace too ([#485](https://github.com/panyam/jaala/issues/485)), so a host tunes its prompts against its own models without a jaala change. `Pack.Prompts` holds the instructions after the card, a front end's instructions by language, the actions' instructions and their tools' descriptions, the lines for a try tried again, a `look` for a plain word and a stuck model, the lines a refused draft and an empty answer go back with, the fallback's note, the reask after a repeated empty draft, the heading over the grounded values, the pick's instructions and its retry line, the compact turn's headings, and `Extract`'s instructions and retry line. A field left empty keeps jaala's, so a host sets only what it changes, and `nl.DefaultPrompts()` gives jaala's text to start from. A few are templates (the actions' instructions, the `values` tool's description, the fix lines, the reask, `LookFound` and `Stuck`), and a replacement keeps every placeholder, in any order with explicit indexes such as `%[2]s`; `Pack.Validate`, and the translator before it asks a model, refuse one that drops or adds any. A field holds its own sentences: the blank lines between it and the rest of a turn stay jaala's.

### Answering with one call

Most questions in a domain apply a concept the host has already written as a relation to a name the question gives: callers of a function, tests reaching a file, what a package depends on. A small model writing a whole program for each is where it fails most, so a pack can list those relations in `Callables` ([#484](https://github.com/panyam/jaala/issues/484)), each with what it answers and a line per argument, in the host's words. The translator then asks the model first to pick one and fill its arguments, or reply `none`. It asks with the pack's `About` and `Card`, the catalogue and the question, not the card or the examples, under a grammar that allows only `none` or a call of a listed relation. A bare call is a program whose rows bind its variables, so `deps.depends_on("app", ?d)` is checked, run, judged and voted on as any draft is. A refused call goes back once, and after a second refusal, a repeat or a `none`, the question is drafted as before in a fresh conversation, so a question no relation fits costs one short reply. A pick is a `Try` with `Mode` `"call"`, and a `none` is a `Step`, so a draft after it still counts as the first try. Over the guide's eight questions, with `imports`, `deps.depends_on` and `pkg` listed, a scripted small model answers six on the first try in about a quarter of the tokens drafting took (`TestEvalCallable` in `frontends/nl`).

## Extracting facts from text

The same loop runs the other way: the translator's `Extract(ctx, text, opts)` turns text (a document, a chat log, a ticket thread) into the facts it states, as an `ns.Changes` the host can apply ([#414](https://github.com/panyam/jaala/issues/414)). It asks the `Config`'s models as `Ask` does, a Runner turn each, the fallback after the model, over an `nl.ExtractSession`, which reads and checks each reply ([#502](https://github.com/panyam/jaala/issues/502)). The prefix lists the vocabulary's base relations, each with its labels, a closed domain's values and its doc, and the model replies with one fact per line:

```
+ owner("app", "bob") from "Bob owns app now"
- imports("app", "api") from "app no longer imports api"
```

`+` is a fact the text states and `-` one it says no longer holds. Each fact is read as a goal of one atom and checked by `datalog.Validate`, so its values are held to the argument's type, closed domain and units exactly as a query's constants are, and a refusal goes back with the line, a caret under the value and the engine's fix (`did you mean "Apache-2.0"?`). A text value and the words after `from` read a backslash as keeping the next character alone, so `"say \"hi\""` is `say "hi"`, the spelling a host stores and a key finds (#444). The words must appear in the text as written, and an added fact cites them as `text:<start>-<end>`, byte offsets into the text, so an answer over the facts explains itself back to the words. A derived relation's facts follow from its rules, so a line adding one is refused. `nl.ExtractGrammar` is the reply's GBNF, the base relations at their arities with a closed domain's values spelled out, which `Extract` sends as `Prompt.Grammar`.

The engine never decides which facts are one (#183), so a pack says it: `Pack.Keys` maps a relation to the argument positions that identify its fact. Under `{"owner": {0}}`, a line adding `owner("app", "bob")` removes the `owner("app", "alice")` that `ExtractOptions.Base` holds, or that an earlier line added, in the same change set. A relation without keys only gains facts. `Pack.ExtractExamples` are texts with the lines they should give, which follow the pack's `About` and `Card`; `Pack.Validate` reads each one, and checks every key names a base relation and a position within its arity, before any model is asked. `MaxTries`, `Fallback`, a repeated draft and `Budget` work as they do for the translator, and the `Trace` records each try with its kind, `span` for words the text doesn't hold and `derived` for a derived relation among them.

## Scoring a translator

`nl.Eval` runs a set of `nl.Case`s, each a question and the rows a right program answers, through a translator and a base, and reports how it went ([#326](https://github.com/panyam/jaala/issues/326)). The translator is a function from a question to a program, its trace and an error, usually a `translator.Translator`'s `Ask`, so a host can wrap its own fallback or tool around it. A program whose rows the translator already ran over `Options.Base` is scored on those; any other runs over the base given to `Eval`. A case failing, in translating or evaluating, fails alone.

The model chooses the program's columns, so a row matches by its values whatever their names and order: `=> ?b, ?a` answers `{"app", "api"}` as well as `=> ?a, ?b` does. Rows match as a multiset, in order only when the case sets `Ordered`, and an absent value is written `absent`. The last example above scores three questions, two needing a second draft.

The `nl.Report` holds each case's `Result` (the program, its trace, the rows it got and whether they passed) and the totals: passes on the first try and after retries, tries, tokens in, out and cached, latency, the refused tries by kind, and how many of the refused check errors carried a fix. That last pair says how often a model was told how to fix its mistake, and a retry spent on an error without one is where an error message could say more. `Report.String` writes it as the example does. When the translator ran the programs over a `Base`, it adds each case's work and the three costliest drafts with the literal that spent the most (`Report.Costliest`), ranked by work rather than time, so two runs rank them the same. jaala's own `TestEval` (`cd frontends/nl && go test -run TestEval -v .`) scores a scripted model and fallback the same way, over eight questions on this vocabulary.

### Outcomes, tags, cost and a run record

A case ends one of three ways ([#536](https://github.com/panyam/jaala/issues/536)). `Result.Outcome` is `pass`, `wrong` or `abstain`, and `Report` counts `Passed`, `Wrong` and `Abstained` apart. A case abstains when the translator's error is an `*nl.Abstained`, so an abstention isn't scored as a wrong answer. A host grading its own agent through `Eval` returns `&nl.Abstained{Reason: nl.AbstainAgent}` when the agent says it doesn't know. A failure of any other kind is wrong.

`Case.Tags` names the kinds of query a question needs, such as `closure` or `join across kinds`, in the host's words. `Report.Summary(prices)` counts pass, wrong and abstain for the run and for each tag. It also gives the run's `Cost`, which covers tokens in, cached and out, model calls, wall time and dollars. `Eval` times each case (`Result.Took`), and the translator counts the model calls behind each try and step (`Try.Calls`, `Step.Calls`). `nl.Prices` maps a model's label to its price per million tokens. A model with tokens and no price is listed in `Cost.Unpriced` rather than counted as free, so a local model is priced at zero explicitly. `Summary.PerCorrect` gives the dollars and seconds per passing case.

`nl.NewRecord(report, prices)` turns a run into a `Record`. A record holds each case's outcome, tags, cost, program, rows and tries, and the `Summary`. The host fills in when it ran, its commit, the question set, the arm, the model and its settings. `Record.Write(dir)` writes a new JSON file per run, so runs from two branches never touch one file. `nl.ReadRecords(dir)` reads a directory back, earliest first, and `nl.HistoryTable` prints a row per run as CSV or Markdown with cost and time per correct answer. A cost with an unpriced model is marked with a `+`, since it is then a lower bound.
